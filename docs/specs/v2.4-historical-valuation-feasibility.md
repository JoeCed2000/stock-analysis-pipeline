## 1. Executive Summary

**Feasibility: PARTIAL** — Historical valuation context is computable using free data sources already in the stack (yfinance), but with important limitations.

- ✅ **Historical price** (monthly/quarterly) — FULLY available (5-10 years of daily OHLCV)
- ✅ **Historical fundamentals** (quarterly) — PARTIALLY available (5-7 quarters detail, 4 years annual)
- ✅ **Computed multiples** (PE, PS, EV/EBITDA, P/FCF, FCF Yield) — COMPUTABLE from price + quarterly data
- ❌ **Industry/sector medians** — NOT available via free sources
- ❌ **Historical forward PE / analyst estimates** — NOT available historically
- ⚠️ **Monthly granularity** — Fundamental data is quarterly; between quarters, fundamentals held constant

**Recommendation**: Proceed with quarterly snapshots (not daily/monthly) computed from yfinance price history + quarterly financial statements. Explicitly mark "sector median" and "forward PE history" as unavailable — do not invent data.

## 4. Proposed Method

### 4.1 Architecture Decision

**Approach**: Quarterly valuation snapshots computed entirely from yfinance data (no new dependencies).

Rationale:
- yfinance is already in the stack, proven reliable in V2.3
- Quarter-aligned data avoids interpolation artifacts
- No new API keys, rate limits, or external dependencies
- Aligns with ADR-002 (deterministic, auditable, rules-based)

### 4.2 Data Flow

```
yfinance.Ticker(ticker)
  ├─ .history(period="5y")              → monthly_close_prices[]
  ├─ .quarterly_financials              → revenue[], net_income[], ebitda[]
  ├─ .quarterly_balance_sheet           → total_assets[], total_debt[], cash[], shares_outstanding[]
  ├─ .quarterly_cashflow                → free_cash_flow[], operating_cash_flow[]
  └─ .info                              → current valuation ratios (snapshot only)

For each quarter (as_of_date = quarter end):
  1. Get month_end_price from history (closest trading day to quarter end)
  2. Extract quarterly fundamentals: revenue, net_income, ebitda, fcf
  3. Extract balance sheet: shares_outstanding, total_debt, cash
  4. Compute TTM values (sum of 4 trailing quarters where available)
  5. Compute multiples:
     - market_cap = price × shares_outstanding
     - enterprise_value = market_cap + total_debt − cash
     - pe_ttm = price / (quarterly_eps × 4)  [or TTM earnings per share]
     - ps_ttm = price / (quarterly_revenue_per_share × 4)
     - ev_ebitda = enterprise_value / (quarterly_ebitda × 4)
     - ev_sales = enterprise_value / (quarterly_revenue × 4)
     - p_fcf = price / (quarterly_fcf_per_share)
     - fcf_yield = quarterly_fcf_per_share / price

For periods where TTM data is insufficient (< 4 quarters of history):
  → mark as "partial" with fewer quarters used
  → if < 1 quarter of data: mark as "insufficient_data"
```

### 4.3 Status Model

```
data_quality:
  "complete"     — All 4 trailing quarters available, all multiples computed
  "partial"      — 1-3 quarters available, multiples computed with fewer periods
  "insufficient" — < 1 quarter of fundamental data, only price available
  "unavailable"  — No data at all for this period
```

### 4.4 Caching Strategy

Unlike the real-time cache (5-min TTL), historical valuation snapshots should:
- Be computed once per ticker and cached with a **multi-day TTL** (fundamentals change quarterly)
- Invalidate on new quarterly filing detection (check if latest quarter date changed)
- Reuse existing `market_cache.py` pattern with adjusted TTLs

### 4.5 Lookback Window

- **Default**: 20 quarters (5 years) — matches `.history(period="5y")` availability
- **Minimum useful**: 4 quarters (1 year) — needed for TTM computation
- **Maximum reliable**: 5-7 quarters (yfinance quarterly data depth)
- **Fallback for older periods**: Annual data from `.financials` (4 years) can fill gaps with lower granularity

## 5. Frontend Integration (Valuation Context without Scoring)

### 5.1 What This Enables

Per V2.4 scope: "Adds valuation context WITHOUT scoring/recommendations"

Frontend can display:
- **Current PE vs 5-year range**: "P/E 24.9 — 5-year range: 15.3 – 38.2"
- **Current EV/EBITDA vs history**: "EV/EBITDA 17.1 — 5-year avg: 22.4"
- **Mini sparkline/chart**: Valuation multiple trend over last 4-8 quarters
- **Narrative context**: "PE is below 5-year median" / "EV/EBITDA near 5-year low"
- **Valuation percentile**: "Current PE is at the 30th percentile of its 5-year range"

### 5.2 What This Does NOT Enable (Intentionally)

- No BUY/HOLD/SELL signal based on history (this is context, not scoring)
- No sector comparison (no sector median data)
- No "cheap/expensive" judgment (just "relative to its own history")
- No growth-adjusted valuation (PEG requires forward estimates)

## 6. Limitations & Risks

| Limitation | Impact | Mitigation |
|---|---|---|
| Fundamental data is quarterly, not monthly | Can't show mid-quarter valuation changes | Use quarterly snapshots only; label clearly |
| yfinance quarterly depth is only ~5-7 quarters | "5-year" context limited for fundamentals | Mark "partial" for periods beyond 7 quarters |
| yfinance API is unofficial, no SLA | Service disruptions possible | Cache aggressively; serve stale data on failure |
| Free tier — no guaranteed historical depth | Some tickers may have less data | Graceful degradation per status model |
| No industry comparison data | Can't say "cheap vs peers" | Explicitly document this limitation in UI |
| Forward-looking metrics unavailable historically | Can't show forward PE trend | Display current forward PE only |
