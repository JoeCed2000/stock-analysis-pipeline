## Scope

Ajout d'une couche de données de marché horodatée et d'un groupe Valuation dans le frontend.

### Backend
- `GET /api/valuation/{ticker}` — endpoint structuré
- Cache avec TTL configurable, gestion rate-limit yfinance
- Champs : `price`, `market_cap`, `enterprise_value`, `ev_source`, `quote_currency`, `quote_timestamp`, `fundamentals_timestamp`, `fx_rate_eur`, `fx_status`, `source`, `served_from`, `status`
- `ev_source` = `reported` (yfinance) ou `computed` (market_cap + debt - cash)
- `status` = `fresh` | `cached` | `stale` | `unavailable`
- `served_from` = `live` | `cache`
- `source` = provider réel (`finnhub`, `yfinance`, `twelvedata`, etc.)
- `fx_status` = `unavailable` pour ce produit (USD-only)

### Frontend
- Groupe Valuation 4×2 : Market Cap, Enterprise Value, P/E TTM, P/S TTM, EV/Sales, EV/EBITDA, P/FCF, FCF Yield
- Footer : `Market data: {status} · Source: {source} · Served from {served_from} · Currency: {quote_currency} · Quote: {timestamp}`
- Tooltip Enterprise Value : `EV source: {reported|computed}`
- Calculs de multiples via `chartUtils.js` (fonctions pures testables)

## Décisions produit

| Décision | Raison |
|---|---|
| Devise = USD | Site SA destiné à un client américain |
| Pas d'EUR affiché | `price_eur`, `market_cap_eur`, etc. = `null` |
| Pas de warning FX | `fx_status` reste côté API uniquement |
| `status` API = source de vérité | Pas d'heuristique locale de fraîcheur |
| `source` ≠ `served_from` | Provider réel vs mode de livraison |

## Cache note

**Les anciennes entrées de cache affichent `source: unknown`.**  
C'est normal : avant le fix `7602759`, le provider n'était pas stocké dans le cache.

- Les nouvelles entrées live doivent persister le provider réel (`finnhub`, `yfinance`, etc.)
- `source: unknown` ne doit pas devenir la valeur normale
- Si le problème persiste après 48h de fetchs live : purge ciblée ou fallback UI
